## 1. 買盤竭盡點 / 賣盤竭盡點（內外盤竭盡）

**課程來源**: ch01, ch03, ch19

**老師原話（逐字、含時間戳）**:
> 「你反而會去找一個竭盡點…內 外盤 外盤 外盤 外盤 / 很多外盤成交 / 那突然一個內盤成交 / 那這就是一個竭盡點 / 這是一個買盤的竭盡點」(ch01 17:26-17:43)
>
> 「從330開始連續性外盤成交 / 這量很大 量超大的 / 9點09分02秒開始連續外盤成交 / 到了9點10分33秒 / 就是一個買盤竭盡點 / 你看 這買盤竭盡點就相對的高點 / 在33.35」(ch01 24:06-24:55，多頭案例)
>
> 「9點16分08秒開始 / 到9點17分09秒 / 這地方就竭盡點 / 連續內盤成交 / 到這點是竭盡點 / 那這個點呢 / 114大概就接近這個當天的最低點」(ch01 24:06-24:55，空頭案例)
>
> 「外內比假如是紅色的話 代表今天偏多 / 外內比100%代表今天全部都是外盤成交 / 外內比 假如剩下0% 1%或是負1% 那代表今天外盤跟內盤一半一半」(ch19 08:18-08:48)

**用途澄清**: 偵測「相對高/低點」(33.35 / 114)、**不是絕對極值**。

**為什麼不實作**:
1. **資料源不可得**：需 tick-level 內外盤標記。
   - FinMind：無 tick-level 內外盤
   - Fubon API：tick stream 有、歷史回放不可用、無「內外盤」標記欄位
2. **量化門檻**：課程示範「連續 4 筆外盤」的形態描述 + 「量很大 量超大的」、**但沒有給「N 筆連續外盤」的硬門檻**。
3. **外內比（ch19）= 部分 proxy**：日粒度外內比有公開資料、但只能反推「整日偏多/偏空」、無法定位「9:10:33 那個竭盡時間點」。

**未來實作條件**:
- 取得 tick-level 內外盤資料源（付費商業 API 或自建）
- 課程後續補充具體量化門檻（連續筆數 / 量門檻）
- 或接受外內比為日粒度 proxy、課程概念「相對高/低點」改用日 K 內外盤比例做近似

## 2. 庫藏股分點標記（粉紅色標記、公司派出手）

**課程來源**: ch10, ch15

**老師原話（逐字）**:
> 「在粉紅色這一段 / 它就是這個庫藏股的分點 / 所以當你看到庫藏股分點 / 像這一檔 兆豐天母 / 這庫藏股分點 / 然後在高檔它又大賣 / 因為它又是庫藏股 / 庫藏股就是公司派 / 它又在低檔大買 / 又在高檔大賣 / 這種就是我們最喜歡的分點」(ch10 01:54-02:26)
>
> 「他就屬於關鍵分點喔 / 因為他是庫藏股的分點 / 這是庫藏股的分點 / 粉紅色就是庫藏股的分點」(ch15 08:41-09:13)
>
> 「在低檔庫藏股之後他大買 / 在高檔大賣 / 那現在呢股價呢就比較長線的偏多」(ch15 10:30-10:41)

**Ranking**：庫藏股分點 + 低買高賣 = 課程列為**「我們最喜歡的分點」/「最強的關鍵分點」**、屬最高 tier 關鍵分點。

**為什麼不實作**:
1. **「分點」標記資料源不可得**：
   - 課程的「粉紅色標記」來自 CMoney 籌碼 K 線軟體 UI、不是 FinMind / Fubon 公開資料
   - FinMind 有 `TaiwanStockTreasuryStock`（公司層級的庫藏股額度公告）、不是「分點層級的庫藏股動作」標記
2. **「×2 加分」乘數**：是 `detector_spec.md` 的建議、**不是課程明示**。課程僅質性說「最喜歡的分點」、沒給量化乘數。
3. **「從公司公告 + 分點動作推測」方法**：**課程沒有教**。Opus xhigh 全文 audit ch10/15 確認無此方法。

**未來實作條件**:
- 取得 CMoney / 籌碼專業版的分點標記
- 或從公司公告與分點動作做交叉推測（精度損失大）

## 3. 大戶 vs 散戶持股比的「持續性 N 週」斜率

**課程來源**: ch14

**老師原話（逐字）**:
> 「就會導致大戶持股比率持續性的上升 / 因為大戶他的持有張數比較多 / 那散戶呢**100 張以下**呢 / 這持股比率持續性的下降 / 因為散戶 10 張 10 張都賣掉了」(ch14 02:55-03:11)
>
> 「第一個呢是大戶持續的增加 / 大戶持續增加代表怎麼樣」(ch14 01:56-02:00)
>
> （空頭對稱版）「是大戶持續減少 散戶持續增加 / 因為剛剛主力賣超的關係 / 所以呢會導致大戶持續性的減少」(ch14 06:35-07:11)

**有明示部分**：
- ✅ **散戶閾值 = 100 張**（ch14 03:03 明示、**不是** 50 / 200 張）— 對應 FinMind `TaiwanStockShareholding` 的「100 張以下」桶
- ✅ **空頭對稱版**：大戶持續減少 + 散戶持續增加（ch14 06:35）

**沒明示部分（concept-only 原因）**：
- ❌ 「持續性 N 週」的具體 N（不是 2 週、3 週、4 週、都沒）
- ❌ 「持續性」斜率定義（vs 上週？vs 上月？絕對值 vs 變化率？）
- 課程只給「機制性敘事」（「因為主力買的張數比較多」「因為散戶 10 張 10 張都賣掉了」）、不是時間長度量化

**現行實作**: `main_chip_holder_v2.py` 用「最近一週 vs 前一週上升」作 proxy（最 conservative 的「N=1 週」）、docstring 已標「課程僅概念、實作以 1 週上升作 conservative 代理」。**散戶閾值已用 100 張**、對應 FinMind 標準桶。

**未來實作條件**:
- 課程後續補充影片給出具體 N 週
- 或 user / backtest 校正最佳 N 後升格到 `extras/`

## 不再列為 concept-only 的項目（已從本清單剔除）

### ~~月線方向（trend up/down）的具體判定~~ — 課程其實有給

**Opus xhigh 2026-06-19 audit 發現**：課程在 ch02 02:48-03:13 明確教**扣抵值判定法**：
> 「月線是 20 日均價線 / 來看這條 這裡是月線下彎 / 那扣抵就是 20 日前價格 / 從這邊開始數 1 2 3 4 5 6 7 8 9 / 數到這邊第 20 個 / 扣抵在左上 月線就往右下 / 扣抵在左上 月線就往下 / 扣抵值比較高 月線往下」(ch02 02:48-03:13)

**`ma20.diff() > 0` 是該方法的數學等價**（差別僅在 today-look-forward vs today-look-backward）、不是 conservative proxy。各 detector docstring 已更新引用 ch02 02:48 扣抵值方法。

### ~~主力買賣超「20 張大買」門檻在不同流動性股~~ — 課程其實有比例化版

**Opus xhigh 2026-06-19 audit 發現**：除了 ch11 02:35 的絕對門檻（0/10/20 張小/中/大買）、課程在 **ch12 02:00-02:45** 給了**比例化門檻**：
> 「最大主力狂進貨…最大買超分點買超量呢 / 就要佔成交量的 20% 以上 / 要佔 20% 以上 / 那當日成交量又要大於 1000 張」(ch12 02:00-02:45)
>
> 「最大主力狂倒貨 / 最大賣超分點的量佔成交量 20% 以上 / 找出當日交量大於 1000 張」(ch12 08:42-09:07，空頭版)

這正好解決「不同流動性股」問題：
- **大盤股**：用 ch11 絕對門檻 (≥ 20 張)
- **小型股**：用 ch12 比例門檻 (≥ 20% 成交量 + ≥ 1000 張)

**已實作**：`scripts/xiaoge/scoring/screener.py::detect_m2_max_broker_loading`（多頭）+ `detect_s2_max_broker_dumping`（空頭）。M2/S2 docstring 已明確引用 ch12 + 20% / 1000 張門檻。

## 何時可以「升格」剩下的 concept-only 項目

依 CLAUDE.md 課程外條件隔離規則：
- 若 user 或老師之後在新章節 / 補充影片給出具體門檻 → 升格進 `scripts/xiaoge/{entry,exit,scoring}/`
- 若 backtest 出強 edge、即使課程沒明說 → 進 `scripts/xiaoge/extras/`、預設 OFF、`--extras` 啟用

**禁止**: 把推測門檻偷渡進 `scripts/xiaoge/` 主目錄。
